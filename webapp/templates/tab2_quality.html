Use Case 1 — Ingestion and data quality

What the pipeline found in the CPD extract, and what it did about it.

A note on the source files. The five CSVs supplied by the CPD were named inconsistently with their contents — the file called chicago_crime_dataset.csv actually held the 77 community areas, while the real crime extract arrived as chicago_district_ps_info.csv. Each file was identified by its header row and re-mapped before any analysis was run. No genuine IUCR file was supplied, so that dimension is reconstructed from the offence attributes carried on each crime row.

Insight

The gaps cluster in the geospatial block — latitude, longitude, x/y coordinates and location go missing together, which is the signature of a failed geocode rather than random loss. Those records keep their district, beat and community codes, so they stay fully usable for every non-map analysis.

Nothing is discarded. Every source row survives into the warehouse with its case number intact, which is what the brief's regulatory-compliance, insurance and public-safety use cases depend on.

The star schema

Why crime type does not live on the crime record.

primary_type and description are attributes of the offence code, not of an individual crime, so they live once in the iucr dimension and are read back through the vw_crime_full view. That keeps the fact table in third normal form and makes it impossible for the same offence to be spelled two different ways in two different rows.

chicago_crime (case_number PK)
    ├── iucr_code      → iucr (primary_type, description, index_code)
    ├── beat_num       → police_beat_info
    ├── district_code  → district_ps_info
    ├── community_code → city_community (population, area, density)
    └── ward_no        → ward_office     (no FK: see below)

Design decision

The ward foreign key is deliberately not enforced. The crime data references wards 1–50 but the supplied ward-office file covers only wards 1–24, so the constraint would reject roughly half the records. Rejecting valid crime data to satisfy a reference-file gap would breach the brief's requirement that no data be discarded, so the gap is documented instead of deleted.
